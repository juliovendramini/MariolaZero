# `VL53L0X` — sensor de distância a laser (I2C)

Arquivo: `libs/vl53.py` · `from vl53 import VL53L0X`

## Para que serve

Mede a distância até o que está na frente dele, de ~3 cm a ~1,2–2 m, com precisão de poucos
milímetros, usando um laser infravermelho (tempo de voo). No robô:

* **Line:** ver o obstáculo antes de bater; achar e seguir as paredes da área de resgate; o
  sensor na garra que vê a vítima entre os dedos.
* **Maze:** ver as paredes dos lados e da frente de cada ladrilho; centralizar no corredor;
  alinhar com a parede (dois sensores do mesmo lado).

## Como funciona

* Cada sensor vai num conector **I2C1 a I2C8**. Todos têm o mesmo endereço; o multiplexador do
  Mariola separa um do outro. A lib seleciona o canal antes de cada conversa.
* O feixe é um **cone de ~25°**: o sensor "vê" uma mancha que cresce com a distância. Perto de uma
  quina ou com o robô torto, ele pode ver a parede do lado.
* Uma medida leva ~**33 ms**. Fora do alcance (nada à vista) ele devolve **8190** (ou 8191).
* Ao iniciar, a lib muda o endereço do sensor de 0x29 para 0x30 (e descobre sozinha em qual dos
  dois ele está na próxima vez).

## Criando o objeto

### `VL53L0X(porta_mux)`
```python
frente = VL53L0X(Portas.I2C5)
```
Faz a inicialização completa (calibração interna, ~100 ms). Lança `ValueError` para canal
inválido e `OSError` se o sensor não responder ("Sensor não encontrado...").

* Crie todos os sensores **uma vez**, no começo.
* Num robô onde o sensor pode não existir, use `try/except` (o exemplo da Line faz isso).

## Ler a distância

### `read_range_single_millimeters()` — o jeito simples
Dispara uma medida, **espera** (~33 ms) e devolve os mm.

* **Quando usar:** testes, calibração, situações sem pressa. Para 3 sensores, são ~100 ms
  parados.

### `solicita_leitura()` + `leitura_mm()` — o jeito rápido
`solicita_leitura()` dispara a medida e volta logo. `leitura_mm()` pega o resultado (se ainda não
ficou pronto, espera até ficar).

```python
for s in sensores.values():          # dispara todos
    s.solicita_leitura()
time.sleep(0.034)                    # UMA espera para todos
d = {nome: s.leitura_mm() for nome, s in sensores.items()}
```

Ou, dentro do laço de controle, sem nunca esperar:

```python
frente.solicita_leitura()
while True:
    ...                               # segue linha, etc.
    if time.time() - t_pedido > 0.036:
        dist = frente.leitura_mm()    # medida pedida na volta anterior
        frente.solicita_leitura()     # já pede a próxima
        t_pedido = time.time()
```

* **Cuidado — leitura velha:** o valor de `leitura_mm()` é de quando a medida foi **pedida**. Se o
  robô girou ou andou muito no meio, ela descreve o lugar antigo. Depois de um giro, descarte a
  primeira leitura ou use `read_range_single_millimeters()`.

### Modo contínuo
`start_continuous(period_ms=0)` liga a medição automática (0 = uma atrás da outra; `period_ms` =
uma a cada N ms) e `read_range_continuous_millimeters()` lê a mais recente. `stop_continuous()`
desliga.

* **Cuidado:** `start_continuous()` **não seleciona o canal do mux**. Com vários sensores, chame
  `sensor.select_channel()` antes. Para vários sensores o par `solicita_leitura`/`leitura_mm` é
  mais simples.

### `timeout_occurred()`
`True` se alguma espera passou do limite desde a última consulta (e limpa o aviso). As esperas
lançam `TimeoutError` depois de 500 ms; trate com `try/except (OSError, TimeoutError)`.

## Problemas no barramento

### `recover()`
Fecha e reabre o canal do mux e reinicia o sensor. Use quando um sensor começar a dar `OSError`
(cabo com mau contato, travou depois de um tranco):

```python
try:
    d = frente.read_range_single_millimeters()
except (OSError, TimeoutError):
    frente.recover()
    d = 8190
```

### `select_channel()` · `close_channel()`
Seleciona/fecha o canal no mux (as leituras já fazem isso).

## Ajustes avançados

| Método | O que faz |
|---|---|
| `set_measurement_timing_budget(us)` / `get_measurement_timing_budget()` | tempo de cada medida (padrão ~33000 µs). Maior = mais preciso e mais lento; menor (ex.: 20000) = mais rápido e mais ruidoso |
| `set_signal_rate_limit(mcps)` | sinal mínimo aceito (padrão 0,25). Menor = alcança mais longe, aceita mais erro |
| `set_i2c_address(addr)` | muda o endereço (a lib já cuida disso) |
| `get_spad_info`, `perform_ref_calibration`, `load_tuning_settings`, `get_vcsel_pulse_period`, `write_byte`, `read_byte`… | uso interno da inicialização |

## Receitas

**Tem parede?** `d < 150` (Maze, com o sensor a ~5 cm da lateral do robô). Teste o limiar no
seu robô: a parede do ladrilho vizinho fica a ~450 mm.

**Ângulo em relação à parede** com dois sensores do mesmo lado, separados por `D` mm:
`math.degrees(math.atan2(d_tras - d_frente, D))`.

**Média contra ruído:** o VL53 varia alguns milímetros. Para alinhar, faça a média de 3–4 leituras.

## Erros comuns

| Sintoma | Causa provável |
|---|---|
| `OSError` / "Sensor não encontrado" | canal errado, cabo invertido, sensor sem energia |
| Sempre 8190 | nada ao alcance, ou sensor tampado/sujo, ou alvo muito escuro/espelhado |
| Distância "pula" perto de quinas | o cone pegou a outra parede |
| Valor certo, mas do lugar antigo | leitura pedida antes de um giro |
| O sensor não vê as vítimas | altura: um VL53 a 5 cm do chão passa por cima de uma bolinha de 4,5 cm |

## No simulador

Feixe em cone, ruído, 8190 fora do alcance, tempo de medida e **altura** de cada sensor (`vl53`
no `robo*.json`: canal, posição, ângulo, altura). Os registradores do VL53L0X atrás do TCA9548A são
emulados, então a lib faz a inicialização normalmente.
